## Root cause (code-proven)
The only code that creates a price matching the observed fingerprint is `backend/server.py:407 sync_stripe_price()`:
```
stripe.Price.create(product=…, unit_amount=amount, currency=currency,
    lookup_key=lookup_key, transfer_lookup_key=True, tax_behavior="inclusive")
```
`amount` comes from a Mongo document's `price` field. `transfer_lookup_key=True` MOVES the lookup_key onto the new price while leaving the old 5.99 price `active=true` — exactly the "created without deactivating the 5.99" symptom. (The deactivation branch — `Price.modify(active=False)` — only runs when an active price with that lookup_key is found first.)

`sync_stripe_price` is invoked from:
- `ensure_stripe_catalog()` at startup (server.py:460) — but ONLY when `read_only == False`, and `read_only = _STRIPE["environment"] == "production"`. So production = read-only; any NON-production instance runs in WRITE mode.
- `PUT /admin/products/{slug}` (server.py:896) when `price` changes and the product has a file — **the per-publication path.**
- `/payments/checkout` (492), another admin path (944), and manual `POST /admin/products/{slug}/stripe-sync` (1015).

`amount = 499` means the DB read returned 4.99 — i.e. the **PREVIEW database** (confirmed: production DB `auben-preview-shop-test_database`.products suivi-sportif = **5.99**). For the create to land on LIVE `acct_1UHr1vA7WGaTzlxD`, that preview-DB-bound instance must be using LIVE `NEW_STRIPE_*` keys.

So: **the 4.99 LIVE prices are written by the app's own `sync_stripe_price` running against the PREVIEW DB with LIVE keys — NOT by the Emergent deploy pipeline, NOT by production (read-only), NOT by a DB migration.** The two in-window creations (11-12, 11-15) coincide with deploy windows but are not produced by any pipeline step. The deploy does restart/wake the preview pod (`wakeup_environment`), and a preview instance runs `ensure_stripe_catalog` in WRITE mode on boot; if that preview pod still holds LIVE `NEW_STRIPE_*` keys (or `PUBLIC_BASE_URL` resolving to production), its startup sync would create 4.99 on LIVE from the preview DB. The current guardrails in `stripe_keys.py::select_stripe_keys` are designed to forbid LIVE keys on the preview URL — so if LIVE writes are still happening, that binding must be checked directly.
